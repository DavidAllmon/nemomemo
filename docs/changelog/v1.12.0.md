## What's new
- **Your reef has a time machine (Cloud).** Cloud reefs can now roll themselves back
  to any nightly snapshot: Settings → Backups → "Go back to an earlier day" lists
  every backup we hold of your reef — pick a date, confirm, and a few minutes later
  your memos, members, and files are back to that morning. We keep a safety copy of
  the present, just in case. 🕰️🐠

## Technical notes
- New reefkeeper-only cloud API: `GET /api/v1/cloud/snapshots` (dates from a
  `snapshots.json` manifest the nightly backup writes) and
  `POST /api/v1/cloud/snapshots/restore` — available even without Stripe env, since
  backups aren't a billing feature. `makeCloudApp` gains a required `dataDir` param.
- Restores are a file-queue handshake in `<volume>/restore/{queue,staged,status}`:
  the host cron `deploy/restore-cloud.sh` does the restic restore + sqlite
  integrity check (restic creds never enter the container), and a new in-app 10 s
  sweeper (`cloud/restore-sweeper.ts`) performs evict → swap → reopen, keeping one
  `reefs/<slug>.pre-restore-<ts>` safety copy.
- `deploy/backup-cloud.sh` now stages at a fixed path (`/tmp/nemomemo-backup-stage`)
  for stable restic paths — the first nightly after this change re-reads all data
  once (storage stays deduplicated) — and writes the manifest.
  `deploy/backfill-snapshot-manifest.sh` fills reef lists for historical snapshots;
  `deploy/cloud-vm-setup.sh` idempotently installs jq + the per-minute restore cron.
- Ships dark: no single-tenant changes; cloud-isolation suite extended (reef-scoped
  snapshot visibility, cross-reef restore refusal, route absent single-tenant).
  Server tests 127 (+10).
