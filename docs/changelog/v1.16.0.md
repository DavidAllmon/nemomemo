## What's new
- **Search got a real upgrade.** Search now understands words instead of just matching letters: typing "swim" finds "Swimming lessons", accents don't matter ("cafe" finds "café"), and multi-word searches find your exact phrase even across commas and line breaks. Results come back instantly, even in a reef with thousands of memos.

## Technical notes
- Migration `0006_fts_search.sql`: external-content FTS5 table `memo_fts` (tokenizer `unicode61 remove_diacritics 2`) over `memo.content`, kept in sync by three SQL triggers (insert / delete / update-of-content) so every write path — including tag rename and restored databases re-migrated at boot — is covered by construction; existing rows are backfilled in the same migration.
- `content.contains(...)` in the filter grammar now compiles to `memo.id IN (SELECT rowid FROM memo_fts WHERE memo_fts MATCH ?)` with user text sanitized into a phrase-prefix query (`"coral reef"*`). `startsWith`/`endsWith` (positional) and token-free inputs (punctuation/emoji) keep the LIKE scan. Dory/bottle time guards remain in the outer query, untouched.
- Behavior change: `contains` matches word prefixes, not mid-word substrings — searching "ish" no longer finds "fish". Feeds stay chronological; bm25 relevance ordering is a possible follow-up.
- The FTS virtual table is raw-SQL only and deliberately absent from `db/schema.ts`.
