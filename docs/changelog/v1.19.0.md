## What's new
- **Search can read your screenshots.** When you attach an image, the reef now quietly reads any text inside it — receipts, whiteboards, signs, screenshots — and search finds it. Snap a photo of a recipe or a parking sign; typing a word from it later pulls the memo right up. It all happens on your own server, and self-hosters can turn it off with one setting.

## Technical notes
- Migration `0007_ocr.sql`: `attachment.extracted_text` column + `attachment_fts` external-content FTS5 table with trigger sync (same pattern as `memo_fts`); rehearsed against a seeded pre-0007 DB.
- New `services/ocr.ts`: injectable `OcrEngine` + `OcrQueue` serialized process-wide (one WASM recognize at a time, cloud-safe); tesseract.js worker is lazy and module-shared; traineddata caches in `data/ocr-cache` on first use (Docker image ships no language files). OCR failures never fail an upload.
- `content.contains(...)` now ORs in matches from linked attachments' extracted text; the outer memo WHERE still gates visibility/Dory/bottles, so attachment text can never out-scope its memo (leak test included).
- Env: `NEMOMEMO_OCR` (default on; `0` disables — air-gapped mode) and `NEMOMEMO_OCR_LANGS` (default `eng`); documented in deploy docs this release.
- tesseract.js postinstall (an OpenCollective banner) is declared skipped in `pnpm-workspace.yaml` `allowBuilds`.
