## What's new
- **Restore a backup right from Settings.** Self-hosted reefkeepers can now upload a
  backup zip and the reef puts everything back exactly as it was — your current data is
  set aside safely first, and the reef restarts itself to finish.
- **Claiming a new Cloud reef shows its progress.** No more silent waiting after
  checkout: a friendly progress bar and status updates keep you company while your reef
  is built, and coming back to a claim link you already used now points you straight to
  your reef instead of showing an error.
- **The Backups page now matches how your reef is hosted.** Cloud reefs see the truth —
  backed up automatically every night, with an export button and rollback on request.
  Self-hosted reefs get both download and restore.

## Technical notes
- `POST /api/v1/instance/restore` (admin, self-host only): zip validated via yauzl
  (zip-slip guarded) + better-sqlite3 readonly `integrity_check` and schema-table
  presence; current `nemomemo.db`(+wal/shm) and `uploads/` renamed to
  `*.pre-restore-<ts>` before swap; restart via new `Config.requestRestart` hook
  (single-tenant entry sets delayed `process.exit(0)`; null in tests and cloud — the
  endpoint refuses on cloud reefs since the process is shared).
- Claim page (`cloud/billing.ts`): inline JS progress (indeterminate bar, staged
  messages, double-submit guard, `prefers-reduced-motion` fallback); burned-token
  GET/POST now resolve to an "already claimed" page when the reef is live; claim
  duration logged as `[cloud] reef <slug> claimed in <ms>`.
- Settings Backups split into cloud/self-host variants keyed off the cloud billing
  probe. Test helper `makeTestApp` now honors `dbPath` overrides (was hardcoded
  `:memory:`); added missing `apiError` import in instance routes.
