## What's new
- **Talk instead of type.** Tap the microphone in the editor, start talking, and your words appear in the memo as you speak — tap again when you're done. It's the fastest way to get a thought into your reef. (Needs an OpenAI API key on self-hosted reefs; see the deploy docs. Already on for Cloud reefs.)
- **Voice clips are still here.** The little arrow next to the microphone records an audio clip instead — it attaches to your memo, plays back inline, and gets its own transcript. On reefs without dictation set up, the microphone just records a clip, same as before.

## Technical notes
- New `POST /api/v1/dictation/session`: mints a short-lived OpenAI Realtime ephemeral key (`/v1/realtime/client_secrets`, session type `transcription`, model `gpt-live-transcribe`, `turn_detection: null` — the model self-segments and rejects VAD). The real API key never reaches the browser; upstream failures answer 502 without leaking it.
- Web `VoiceControls` consolidates dictation + clip recording: browser connects to OpenAI directly over WebRTC (`/v1/realtime/calls`, `oai-events` data channel); `…transcription.delta` events feed a live preview line, `…completed` phrases insert into the TipTap editor via `insertText`; tapping stop flushes any un-finalized words. Falls back to MediaRecorder clip capture when `dictationEnabled` is false.
- `InstanceProfileDto.dictationEnabled` (additive) gates the UI; env `NEMOMEMO_DICTATE_KEY` / `NEMOMEMO_DICTATE_MODEL`; new `UPSTREAM` (502) error code. Docs: deploy.mdx gained "Live dictation" + env rows.
