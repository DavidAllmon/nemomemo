## What's new
- **Keyboard shortcuts.** Press `c` to start writing, `/` to search, `j` and `k` to walk
  your feed, `e` to edit what you've landed on, `Enter` to open it — and `?` any time for
  the whole list. They all stand down while you're typing, so the editor keeps every key
  it needs.
- **Go fish.** A button in the sidebar swims up one random memo from your reef. Good for
  the days you don't know what you're looking for.
- **Pin your tags.** Hover a tag in the sidebar, click the star, and it stays at the top
  where you can reach it — up to twenty, in the order you pin them.

## Technical notes
- `GET /api/v1/memos/random` builds its WHERE through `buildMemoListWhere` and picks with
  `ORDER BY RANDOM() LIMIT 1`, so an expired Dory memo, a bottle still at sea, a comment,
  an archived memo, or another member's memo can never be fished up; eight tests draw
  twenty times each. Registered before `/:uid` (route-order trap).
- `pinnedTags` (max 20) added to `userGeneralSettingSchema` — no migration, user settings
  are JSON and `setUserGeneral` merges + reparses. `useTogglePinnedTag` derives the next
  list from the freshest cache and writes it back optimistically, so two quick clicks
  compose instead of the second clobbering the first from a stale render closure.
  `TagRow` lifted to module scope so tag rows stop remounting on every sidebar render.
- Shortcuts live in one `window` keydown listener (`web/src/hooks/use-shortcuts.ts`) that
  bails on modifier keys, editable targets (TipTap is contenteditable), and any open
  `[role="dialog"]`; ⌘K stays in `AppShell`. The feed cursor is read from the DOM
  (`document.activeElement.closest('[data-memo-card]')`) rather than React state, so it
  survives feed re-renders. `MemoCard` gained `data-memo-card` / `data-memo-uid` /
  `tabIndex={-1}` and an `sr-only` `[data-memo-edit]` button, since Edit itself lives
  inside a dropdown.
- `c` pressed on another page carries `{ compose: true }` in router state into
  `RichEditor`'s own `autofocus` option rather than dispatching a one-shot event — the
  event would fire long before the lazy editor chunk mounts, and polling for the handle
  can hit a StrictMode-destroyed TipTap instance. Home consumes the state once so
  returning to that history entry doesn't re-steal the cursor.
- Docs: keyboard shortcuts + the new retrieval views in `memos.mdx`, tag pinning in
  `tags.mdx`.
