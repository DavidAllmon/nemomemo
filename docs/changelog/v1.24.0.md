## What's new
- **Deleting has an undo now.** A memo you delete goes to a new **Trash** and waits
  there for seven days before it's really gone. Restore it with one click, or clear the
  trash yourself when you're sure.
- **Comments and attachments travel with the memo.** Restore it and everything comes
  back exactly where it was — an archived memo returns to your archive, not your
  timeline.
- **While it's in the trash, it's out of sight.** Not in your timeline, not in search,
  not behind an old share link. Its page says the memo swam away, even to you.
- **Dory hasn't changed.** A memo you asked Dory to forget still fades on Dory's
  schedule — the trash is for the ones you deleted on purpose. 🐟

## Technical notes
- Migration **0008** adds a nullable `memo.deleted_at` plus a partial index for the
  sweep — a fourth guard alongside Dory and bottles rather than a third `row_status`,
  whose CHECK constraint would need a table rebuild.
- The guard lands in the two places that already decide who sees a memo:
  `buildMemoListWhere` (every list *and* aggregation — feeds, tags, stats, search,
  Go fish, the gallery) and both functions in `acl.ts` (`checkMemoRead` for the JSON API
  and the raw file server, `canGlimpseMemo` for relation stubs and inbox snippets). It
  hides the memo from its creator too — `/memos/trash` queries `deleted_at` directly.
  The comments query hand-rolls its own WHERE and needed the guard added by hand; a
  13-case test walks every read path so the next one can't be missed silently.
- `purgeMemos()` in `services/purge.ts` is now the single hard-delete cascade (comment
  memos, attachment rows, files unlinked after commit), shared by permanent delete, the
  Dory sweeper, and the new `sweepTrash`. The trash sweep runs as **step 5 of the one
  scheduler tick** — no new interval. The Dory sweep now skips trashed memos, so
  `dory_forgotten_count` no longer counts memos you threw away yourself.
- Endpoints: `DELETE /api/v1/memos/:uid` is now a soft delete (idempotent — deleting
  twice keeps the original clock; an admin's moderation lands in the *creator's* trash),
  `?permanent=1` purges outright, plus `GET /memos/trash`, `POST /memos/trash/empty`,
  and `POST /memos/:uid/restore`. `MemoDto` gained `deletedAt`;
  `TRASH_RETENTION_SECONDS` lives in shared.
- `memo_fts` needs no change: a soft delete leaves content untouched, so the row stays
  indexed and unfindability comes from the query guard. A permanent delete drops the row
  and the existing trigger follows — the FTS sync test now asserts both.
- `MemoCard` gained a `readOnly` mode (no action menu, reactions, or checkbox toggling)
  so trash entries don't offer actions that would silently do nothing.
