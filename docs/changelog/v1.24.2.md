## What's new
- **The sidebar stays put.** Scrolling a long page — the calendar especially — used to
  drag the whole sidebar up off the screen with it. Now only the page scrolls.
- **Everything in the sidebar is reachable again.** On shorter screens the account menu
  could slide off the bottom, putting Settings and Sign out out of reach. Your reef
  name and your account now stay pinned top and bottom, and the list between them
  scrolls.

## Technical notes
- **Document scroll:** `MemoCard`'s hidden edit target (the `e` shortcut's click
  target, added in v1.23.0) used Tailwind's `sr-only`, which is `position: absolute`.
  `main` was `position: static` and therefore not a containing block, so those buttons
  resolved against the initial containing block, escaped `main`'s `overflow-y: auto`
  clip, and stretched `documentElement.scrollHeight` to the last card's bottom — the
  document scrolled and carried the fixed-height `aside` with it. Fixed at both ends:
  the button is now `hidden` + `aria-hidden` (`HTMLElement.click()` fires on
  `display: none`, and the ⋯ menu already exposes Edit to screen readers, so `sr-only`
  was a duplicate control), and `main` is `relative` so future absolutely-positioned
  descendants stay clipped. Verified across all 13 routes: `documentElement` no longer
  exceeds `clientHeight` and `window.scrollY` stays 0.
- **Sidebar overflow:** the old structure let only the tag list scroll
  (`min-h-0 flex-1 overflow-y-auto` around `TagTree`), so once the fixed rows — nav,
  mini-calendar, views, and this session's additions (Calendar, Trash, Go fish, the
  streak line, the Pinned section) — exceeded the viewport, the tag area collapsed to
  0px and the sidebar's `overflow-hidden` clipped the account block entirely. Below
  ~800px of viewport height Settings and Sign out were unreachable. Brand and account
  are now `shrink-0` and everything between shares one scroller; measured good from
  900px down to 380px, and inside the mobile drawer.
