## What's new
- **Let your scripts write to your reef.** **Settings → Tokens** mints an access token
  you can hand to a phone shortcut, a script, or a bot — no password sharing. The
  token is shown once; copy it then, and revoke it any time.
- **Two kinds of token.** *Full access* does everything with memos. *Create only* can
  post new memos and nothing else — not even read your reef back — which is the one to
  put on a device that might get lost.
- **A token is never a way into your account.** No token can change your email or
  password, make more tokens, or do anything admin. Those still need you, signed in.

## Technical notes
- Migration 0010 adds `access_token` (SHA-256 of an opaque `nm_…` token, the same
  design as `user_session`; the plaintext is never stored). Not bcrypt on purpose:
  256-bit random tokens have nothing to brute-force, and an unauthenticated bcrypt
  path would be a DoS surface.
- `viewerMiddleware` resolves the session cookie first and only then
  `Authorization: Bearer …`, so a browser session is never downgraded to a token's
  narrower powers; `last_used_ts` is touched at most hourly.
- Two guardrails, both tested: `requireSessionViewer` (403s token-borne requests) on
  token management, `/users/-/account`, and `requireAdmin`; and one `createOnlyScopeGate`
  mounted on the API router that allows a CREATE_ONLY token exactly `POST /memos` and
  `POST /attachments` — new routes are confined by default rather than by remembering.
- `server/src/test/access-tokens.test.ts` (17 cases) covers every deny path;
  `cloud-isolation.test.ts` gained a cross-reef token replay test.
