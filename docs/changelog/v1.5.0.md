## What's new
- **Your words are yours alone.** Only the person who wrote a memo or comment
  can edit it now — reefkeepers can still tidy up (archive or remove things),
  but nobody can rewrite what you said.
- **Edits wear a little badge.** When a memo or comment has been reworded, it
  shows "edited" next to the timestamp — hover to see exactly when. Pinning or
  archiving doesn't count; only actual rewording does.
- **The inbox learned the difference between read and gone.** Notifications now
  flow Unread → Read → Archived: opening one marks it read, "Mark all read"
  keeps things findable instead of hiding them, and there's a delete button
  when you want something gone for good.

## Technical notes
- PATCH /memos/:uid: content/visibility/dory/pinned/attachmentUids/
  relatedMemoUids require `creatorId === viewer.id` (403 otherwise); rowStatus
  stays creator-or-admin, DELETE unchanged (creator-or-admin). Web: action menu
  splits `isCreator` (edit/pin/dory/tasks, inline checkboxes) from `isOwner`
  (archive/delete).
- `updatedTs` is set only when content changes (was: every PATCH). Empty
  patches no longer hit Drizzle with an empty SET. MemoCard renders
  "· edited" + absolute-time tooltip when `updatedTs > createdTs`.
- Migration `0003_inbox_read_status.sql` rebuilds `inbox` with status CHECK
  ('UNREAD','READ','ARCHIVED'); read-all sets READ; GET /inbox accepts
  `status=READ`; clicking a notification PATCHes it READ. Rehearsed against a
  seeded pre-0003 DB.
- Suite: 90 server tests (7 new in edit-rules.test.ts).
