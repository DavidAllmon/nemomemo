# Trash (undo delete) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deleting a memo moves it to a Trash that holds it for 7 days before the
scheduler hard-deletes it — the first item of Wave 3 in `docs/ROADMAP.md`, and the
foundation of that wave's story: *nothing is ever lost unless you asked Dory.*

**Architecture:** A nullable `memo.deleted_at`, exactly like `forget_at` and
`surface_at` before it — not a third `row_status`, whose CHECK constraint would need
a table rebuild and whose value every existing query already branches on. Trash is
therefore a **fourth guard** that joins the Dory and bottle guards in the two places
that already decide who sees a memo: `buildMemoListWhere` (every list and
aggregation) and `acl.ts` (every single-memo read, the file server included). Unlike
the bottle guard, this one hides the memo from its creator too — the creator reaches
it only through `/memos/trash`, which queries `deleted_at` directly. The hard delete
that DELETE used to do inline becomes `purgeMemos()`, one helper shared by the
permanent-delete route, the Dory sweeper, and the new trash sweep.

**Tech Stack:** Hono + Drizzle + better-sqlite3 (hand-rolled migrations), React 19 +
TanStack Query v5, vitest.

**Spec:** `docs/ROADMAP.md` § "Wave 3 — Trust & garden-tending", row **Trash (undo
delete)**: "Deleted memos linger 7 days (`deleted_at` + scheduler sweep) before hard
delete. The safety net people expect; do first — history builds on the same mindset."

## Global Constraints

- **Ships as v1.24.0** via the two-run `pnpm release minor` + `git push
  --follow-tags`, changelog carrying BOTH sections. Green first:
  `pnpm typecheck && pnpm test && pnpm build`. Push to main is production for a
  paying customer within minutes.
- **Every memo read path gets the new guard.** Grep for
  `forget_at IS NULL OR forget_at > ?` and add `deleted_at IS NULL` beside every hit;
  do the same in `acl.ts`. A missed path leaks deleted memos — the exact class of
  silent bug GOTCHAS.md exists to prevent.
- **Migrations are hand-rolled**: a new numbered `.sql` in
  `server/src/db/migrations/` (next is **0008**) **plus** the matching edit to
  `db/schema.ts`. Never edit a shipped migration. Rehearse against a seeded
  pre-migration DB (the 0006/0007 pattern).
- **New time-based work goes in the scheduler tick**, never a new interval.
- **New static memo routes register before `/:uid`** in `routes/memos.ts`.
- **No payload change**, so no boot backfill. `memo_fts` is external-content and keyed
  on content, which soft delete never touches — no FTS work, and the outer WHERE
  gates search results.
- Voice: reef voice, clarity first. Public docs: `site/content/docs/memos.mdx`'s
  "Deleting" section is currently wrong the moment this ships — update it in the same
  release. No env vars or admin flows, so `deploy.mdx`/`admin.mdx` are untouched.

DELETE becomes:

```ts
  app.delete('/:uid', (c) => {
    const memo = ownedMemo(c, c.req.param('uid'));
    if (c.req.query('permanent') === '1') {
      purgeMemos(db, config.uploadsDir, [memo.id]);
      return c.json({ ok: true, trashed: false });
    }
    // Soft: the memo and its comments go to the creator's trash together, and
    // an already-trashed memo keeps its original clock (deleting twice must not
    // extend the stay).
    const now = nowSeconds();
    if (memo.deletedAt == null) {
      const commentIds = db
        .select()
        .from(memoRelations)
        .where(and(eq(memoRelations.relatedMemoId, memo.id), eq(memoRelations.type, 'COMMENT')))
        .all()
        .map((relation) => relation.memoId);
      const mark = db.$client.transaction(() => {
        const stmt = db.$client.prepare('UPDATE memo SET deleted_at = ? WHERE id = ?');
        stmt.run(now, memo.id);
        for (const id of commentIds) stmt.run(now, id);
      });
      mark();
    }
    return c.json({ ok: true, trashed: true });
  });
```

```ts

    const memo = ownedMemo(c, c.req.param('uid'));
    if (memo.deletedAt == null) throw apiError('INVALID_ARGUMENT', "That memo isn't in the trash");
    const commentIds = db
      .select()
      .from(memoRelations)
      .where(and(eq(memoRelations.relatedMemoId, memo.id), eq(memoRelations.type, 'COMMENT')))
      .all()
      .map((relation) => relation.memoId);
    const restore = db.$client.transaction(() => {
      const stmt = db.$client.prepare('UPDATE memo SET deleted_at = NULL WHERE id = ?');
      stmt.run(memo.id);
      for (const id of commentIds) stmt.run(id);
    });
    restore();
    const restored = getMemoByUid(db, memo.uid)!;
    return c.json({ memo: buildMemoDtos(db, [restored], c.get('viewer'))[0] });
```

- [ ] **Step 5: The sweep, in the one tick**

```ts
// server/src/services/trash-sweeper.ts
/** Purge memos that have sat in the trash longer than the retention window. */
export function sweepTrash(
  db: Db,
  uploadsDir: string,
  retentionSeconds = TRASH_RETENTION_SECONDS,
  now = nowSeconds(),
): number {
  const ids = (
    db.$client
      .prepare('SELECT id FROM memo WHERE deleted_at IS NOT NULL AND deleted_at <= ?')
      .all(now - retentionSeconds) as { id: number }[]
  ).map((row) => row.id);
  return ids.length === 0 ? 0 : purgeMemos(db, uploadsDir, ids);
}
```

In `scheduler.ts`: add `purged: number` to `SchedulerTickResult`, call
`sweepTrash(db, deps.uploadsDir, TRASH_RETENTION_SECONDS, now)` as **step 5** after
the Dory sweep, and return it. Do not add an interval.
